# 07. 금융 백엔드 — 안전결제(가상 거래) · 1원 인증 · 양쪽 수령 확인 (2026-11-25)

## 정책: 왜 '가상 거래'인가
- 실제 돈을 받거나 보관 · 이체하면 PG 계약 · 전자금융업 등록이 필요하다. 스바다는 **비영리 시연용**이라
  실제 돈을 한 푼도 움직이지 않는다(실제 PG · 은행 API 를 부르는 코드가 없음).
- 잔액 · 결제 · 보관 · 정산 · 환불은 전부 결제 서비스(sbada-payment) DB 안의 숫자다.
- 화면에는 **"시연 모드 · 가상 거래"** 를 표시한다. 문구는 `GET /api/payment/health` 의 `label` 을 그대로 쓴다.
- 발표 멘트 예: "물물교환에서 차액이 생겼을 때, 두 사람이 물건을 받은 뒤에 차액이 지급되는 과정을 가상 거래로 보여 드리겠습니다."

## 흐름
```
교환 요청(+추가 금액 조건) ─▶ 낼 사람이 안전결제(보관 HELD, 수수료 5% 낸 사람 부담)
   ─▶ 수락(성사) ─▶ 두 사람 모두 '물건 받았어요'(양쪽 수령 확인 2/2) ─▶ 정산(RELEASED, 받는 사람 지갑)
   └▶ 거절 · 취소 · 받는 사람이 돌려줌 ─▶ 환불(REFUNDED, 낸 수단으로 전액)
   └▶ 아무도 확인 안 해도 성사 72시간 뒤 자동 정산 / 환불 호출이 유실돼도 1분마다 대사(reconcile)로 다시 환불
```

## API (앱은 전부 메인 서버 8097 로 부름)
| 메서드 | 주소 | 설명 |
|---|---|---|
| POST | /api/exchanges | `extraAmount`, `extraPayer`(ME·OTHER) 추가 가능 |
| POST | /api/exchanges/{id}/extra | 추가 금액 제안 · 요구 · 없애기 `{"amount":30000,"payer":"ME\|OTHER"}` (결제 전까지) |
| POST | /api/payments/escrow | 안전결제 `{"exchangeId","amount","method"}` method: CARD·KAKAOPAY·TOSSPAY·TRANSFER·WALLET |
| GET | /api/payments/escrow?exchangeId= | 보관 상태(당사자만) |
| POST | /api/exchanges/{id}/complete | '물건 받았어요' — 두 당사자 각각. 둘 다 누르면 정산 |
| POST | /api/exchanges/{id}/refund-extra | 받을 사람이 돈을 돌려줌 → 환불 |
| POST | /api/wallet/accounts/verify | 1원 인증 시작(시연: 입금자명 `쓰바다 1234` 를 응답 demoMemo · 알림으로) |
| POST | /api/wallet/accounts/verify/{id}/confirm | 숫자 4자리 → 계좌 등록(5분 · 5번) |
| POST | /api/wallet/sandbox/reset | [테스트] 내 잔액을 10만 원으로 |

ExchangeView 추가 필드: `extraAmount`, `extraPayerId`, `extraDirection`(I_PAY·I_RECEIVE), `paymentStatus`
(NONE·PAID_HELD·RELEASED·REFUND_PENDING·REFUNDED), `iReceived`, `otherReceived`.

## 서비스 사이
- 결제 서비스 → 메인: `GET /internal/exchanges/{id}`(누가 · 누구에게 · 얼마 확인), 아웃박스 이벤트
  `ESCROW_HELD · ESCROW_RELEASED · ESCROW_REFUNDED`(exchangeId 포함) → 교환의 paymentStatus 갱신 + 알림
- 메인 → 결제 서비스: `POST /internal/escrow/release · refund` (헤더 X-Internal-Token, 멱등)
- DB: 메인 `V18__exchange_extra_payment.sql`, 결제 `V2__escrow_and_verification.sql`

## 검사 · 시연
- `전체검사.command`: EscrowApiTest(결제) · ExchangeExtraPaymentTest(메인) 포함
- `결제_샌드박스_테스트.command`: 서버 두 개를 켜고 실제 API 로 시나리오 전체(1원 인증 → 결제 → 양쪽 수령 확인 → 정산 → 출금 → 취소 환불)
- `폰_USB_시연.command`: 휴대폰을 USB 로 꽂고 시연(안드로이드는 adb reverse 로 케이블만, 아이폰은 같은 와이파이)
