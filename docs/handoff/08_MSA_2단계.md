# 08. MSA 2단계 — 서버 3개 · gRPC · Kafka · GraphQL (2026-11-25)

자세한 그림과 원칙은 `docs/msa.md`. 여기는 "이어서 일할 사람"이 알아야 할 것만.

## 무엇이 어디로 갔나
| 기능 | 예전(메인) | 지금 |
|---|---|---|
| 물건 · 사진 · AI 가격 · 검열 · 요약 · 추천 피드 · 찜 | `sbada-server` 의 item · image · ai · recommend 패키지 | **`sbada-item`**(8099 · gRPC 9099) |
| 회원 · 교환 · 채팅 · 알림 · 푸시 | 메인 | 메인 그대로(8097 · gRPC 9097) |
| 지갑 · 안전결제 · 출금 | `sbada-payment`(HTTP 이벤트) | 결제 서버(8098 · gRPC 9098), 이벤트는 Kafka |

- 메인 서버는 물건을 `items/ItemCatalog`(gRPC) 로만 본다. 교환 · 채팅 표에는 물건 **번호**(`offeredItemId` · `targetItemId` · `itemId`)만 있다.
- 앱 요청 주소는 그대로 8097. 게이트웨이(`gateway/ItemGatewayController`)가 물품 경로를 8099 로 넘긴다.

## 서비스끼리 말하는 법
| 방식 | 파일 | 규칙 |
|---|---|---|
| gRPC 배달부 | `sbada-proto/proto/sbada/**/v1/*.proto` | 필드 번호 고정, `x-internal-token` 메타데이터, 오류 설명 `"코드|메시지"` |
| Kafka 허브 | 각 서버 `events/`(`EventPublisher` · `OutboxRelay` · 컨슈머) | 같은 트랜잭션에 `outbox_events` 기록 → 1초마다 전송 → 받는 쪽 `processed_events` 로 중복 제거 |
| GraphQL | `sbada-item/src/main/resources/graphql/schema.graphqls`, `graphql/ItemGraphqlController` | 앱 목록 조회 전용. 오류는 `errors[0].extensions.code` 에 REST 와 같은 코드 |

이벤트 목록
- 물품 → `sbada.item.events`: `ITEM_CREATED`, `ITEM_VIEWED`(메인이 취향 학습), `ITEM_STATUS_CHANGED`(HIDDEN · HELD · TRADED → 메인이 대기 중 교환 자동 취소)
- 물품 → `sbada.notifications`: `NOTIFY`(찜 · 검열 보류 알림을 메인이 보냄)
- 메인 → `sbada.exchange.events`: `EXCHANGE_REQUESTED`(물품 서버가 요청 수 +1), `EXCHANGE_ACCEPTED`
- 메인 → `sbada.user.events`: `USER_UPDATED`(물품 서버 판매자 정보 갱신)
- 결제 → `sbada.payment.events`: 지갑 · 결제 이벤트(메인이 알림)
