## A. 시작 화면 ⬜ (디자인: `Start`)
- 화이트 모드. 위에서부터: 로고 글자 **sbada**(Fredoka 600, "sba" #2B2B2B + "da" #4F9A57) → 문구 **“쓰던 물건으로 세상을 바꾸다”**(Gowun Batang 700, #4A5058)
  → 재활용 고리 일러스트(사용자가 직접 만든 그림, 누끼 PNG, 위아래로 천천히 둥실 움직임) → 버튼 4개 → "먼저 둘러보기 →".
- 버튼(모두 리퀴드 글래스, 로고는 동그랗게): **Google 계정으로 시작**(민트 유리, 주 버튼) · Apple 계정으로 시작 · 카카오로 시작 · 네이버로 시작(흰 유리).
  로고 이미지는 사용자가 준 파일(카카오 · 네이버 · Apple · Google 타일). 실제 앱에는 각 사 공식 로그인 버튼 에셋을 쓴다.
- 이메일 · 아이디 로그인 버튼은 뺐다(기존 아이디 로그인 화면은 남아 있음).
- 실제 로그인: 카카오만 구현됨. Google · Apple · 네이버 로그인은 서버 `/api/auth/{provider}` + 앱 SDK 가 새로 필요. Apple 로그인은 유료 개발자 계정 필요.

## B. 거래 중 추가금 (교환 + 돈) 🟡
결제 서비스의 `POST /api/payments/extra`(즉시 지급) 는 있음. 아래 흐름(교환 요청에 묶인 추가금 + 안전결제)은 **구현 필요**.

### B-1. 보내는 사람 (디자인: `Propose`, `ChatExtra`, `PayExtra`, `PayDone`)
1. 교환 제안 시트: 내 물건 ⇄ 상대 물건(AI 가치 표시) + AI 가치 차이 안내.
2. **추가금 얹기** 스위치 + 금액(빠른 버튼: 차액만큼 / +1만 / +5만). **물건 없이 돈으로만 사기** 옵션.
3. 상대가 수락하면 결제: 금액 + **수수료 5%(보내는 사람 부담)**. 결제수단: 신용·체크카드 · 카카오페이 · 토스페이 · 계좌이체(카카오뱅크 · 토스뱅크).
4. 상대가 추가 요금을 **요구**하면 채팅방에 카드: [거절] [금액 조정] [결제하고 수락]. 결제 화면에서 금액은 잠김(수정 불가).
5. 결제 완료 = 돈은 **앱이 보관(에스크로)**. 교환 완료 후 상대에게 지급.

### B-2. 받는 사람 (디자인: `RecvOffer`, `RecvBuy`, `RequestExtra`, `RecvChat`, `RecvPaid`)
1. 받은 제안(물건 + 추가금): 주는 것 / 받는 것 + 가치 비교 → [거절] [금액 다시 제안] [수락하기]. 수수료는 받는 사람이 내지 않음.
2. 받은 구매 요청(돈으로만): 제시 금액 vs AI 가치 → [거절] [역제안] [xxx원에 팔기].
3. 추가 요금 요구하기: 금액(차액 / 절반 빠른 버튼) → [그냥 수락] [xxx원 요구하기].
4. 채팅방 결제 상태 카드: 요구 → 결제 완료(앱 보관 중) → 만나서 교환 → 지갑 지급. [교환 완료] 버튼.
   지급 조건: 두 사람 모두 교환 완료, 또는 3일 동안 신고 없음.
5. 교환 완료 → 푸시 "추가 요금이 들어왔어요" + 지갑 잔액 + [거래 후기 쓰기] [출금하러 가기].

### B-3. 구현 제안
- 메인 서버 `exchange_requests` 에 `extra_amount`, `extra_direction(OFFER|REQUEST)`, `cash_only`, `payment_status(NONE|REQUESTED|PAID_HELD|RELEASED|REFUNDED)` 추가(Flyway V18).
- 결제 서비스에 보관(HOLD) → 지급(RELEASE) → 환불(REFUND) 원장 타입 추가. 교환 상태는 이벤트로 주고받는다(`exchange.completed` → 지급).
- 실제 서비스는 PG **지급대행** 필요(전자금융거래법). 지금은 시연용 숫자만 이동.

## C. 지갑 ✅ (디자인: `Wallet`, `Withdraw`, `WithdrawDone`)
- 잔액(처음 시연 10만 원) · 출금/충전 · 출금 계좌(뒷자리만, 암호화 보관) · 거래 내역.
- 출금: 계좌 선택 → 금액(전액 버튼) → "출금되었습니다" 알림창 + 푸시.

## D. AI 가격 분석 설명 🟡 (디자인: `Register`)
- 카드: "Gemma AI 가격 분석 · 카테고리" → 가격 → 적정 범위 · 신뢰도 → 구분선 →
  **가격 분석 결과** (오른쪽: **정가: 280,000원 (AI 추정)**) → 감가 이유 목록:
  `1. 출시 2년 지난 모델 −70,000원` / `2. 케이스 모서리 생활 흠집 −40,000원` / `3. 이어팁 교체 필요 −20,000원` → 앱 시세 보정 한 줄.
- 서버 프롬프트 · 정가 저장은 구현됨(미검증). 앱은 지금 reason 문자열을 그대로 보여 줌 →
  더 예쁘게 하려면 AI 가 `deductions: [{reason, detail, amount}]` 배열을 따로 주게 바꾸고 앱에서 번호 · 금액 정렬해 그린다.
- "이 가격대(±30%) 이웃 물건 N개와 매칭돼요" 줄은 디자인에서 뺐다. 앱(`register_item_screen.dart` `_nearbyMatches`)에는 아직 남아 있음.
