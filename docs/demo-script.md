# 스바다 시연 대본

교재 12장 1.4의 시간 배분(**소개 15초 + 기능 시연 50초 + 코드 설명 35초 + 확인과 과제 20초 = 2분**)에 맞췄습니다.
발표 시간이 길게 주어지면 아래 "5분 버전"을 씁니다. 원고는 외우지 말고 **목적 → 행동 → 확인 결과** 순서만 기억하세요.

## 0. 발표 전 준비 (10분 전)

| 할 일 | 명령 / 확인 |
|---|---|
| 서버 켜기 | `scripts\run-server.bat` → 브라우저 http://127.0.0.1:8097/ 에 "UP" |
| 서버 점검 | 새 cmd 창에서 `scripts\smoke-test.bat` → 11개 항목 기대값과 일치 |
| 에뮬레이터 | `Medium_Phone_API_37.0` 실행 |
| 앱 실행 | `scripts\run-app.bat` (API_BASE_URL=http://10.0.2.2:8097) |
| 로그인 | 에뮬레이터: **minji / sbada1234** (온보딩은 이미 완료된 계정) |
| 알림 시연용 | cmd 창을 하나 더 열어 `scripts` 폴더에 두기 → `demo-send-request.bat` |
| AI 상태 | http://127.0.0.1:8097/api/ai/status — `active` 가 google/ollama 면 Gemma, fallback 이면 "AI 미연결" 이라고 미리 말한다 |
| 사진 | 에뮬레이터 갤러리에 등록할 물건 사진 1장 넣어 두기(파일을 에뮬레이터 창에 끌어다 놓으면 됨) |

계정: `minji`(디지털·취미 선호) · `junho`(스포츠·도서·디지털) · `seoyeon` · `dohyun` / 비밀번호 모두 `sbada1234`

| 1:05–1:40 코드 설명 | `RecommendationService.java` 의 점수식 / `ExchangeService.accept` | "매칭 점수는 가격 유사도 40%, 내 선호 25%, **상대 선호 20%**, 신선도 10%, 상태 5%입니다. 물물교환은 양쪽이 서로 원해야 하니 상대 선호를 넣었습니다. 수락은 받은 사람만 가능하고, 다른 사람이 누르면 403, 이미 끝난 요청은 409입니다." |
| 1:40–2:00 확인과 과제 | `smoke-test` 결과 / 테스트 보고서 | "코드 초안은 Claude Code가 작성했고, JUnit 테스트와 cmd curl 점검, 에뮬레이터 시연은 제가 직접 실행해 확인했습니다. 남은 과제는 앱이 꺼져 있을 때의 FCM 푸시를 실기기에서 확인하는 것입니다." |

> 마지막 20초의 "직접 확인한 것"은 **실제로 실행한 것만** 말합니다(12장 2.4). FCM은 키를 넣고 실기기에서 확인하기 전까지 "구현했지만 확인하지 않았다"고 말하세요.

## 2. 5분 버전 (추가 장면)

1. **온보딩** (40초): 로그인 화면에서 **새 계정 가입** → 처음 들어오면 온보딩 화면이 자동으로 뜸(또는 계정정보 → 취향 다시 고르기). "처음 설치하면 바꾸고 싶은 종류·키워드·가격대를 고릅니다. 고른 카테고리는 선호도 1.0으로 저장되고, 이후 구경·채팅·요청·교환 때마다 `w ← w + rate·(1−w)` 로 학습됩니다."
2. **채팅** (40초): 매칭 결과 하나 → 채팅하기 → 메시지 전송. PC 브라우저나 두 번째 에뮬레이터에서 상대 계정으로 보면 바로 도착. "채팅은 WebSocket으로 보내고, 서버가 DB에 저장한 뒤 두 사람에게 보냅니다. 연결이 끊기면 REST로 대신 보냅니다."
3. **DB 확인** (40초): http://127.0.0.1:8097/h2-console → `docs/database.md` 의 SQL. "AI의 원래 가격(raw_price)과 보정된 최종가(final_price), 민지의 선호도가 올라간 것을 직접 볼 수 있습니다."
4. **예외 상황** (30초): 이미 수락한 요청을 다시 수락 → 409 메시지. "같은 물건은 한 번만 교환됩니다."

## 3. 예상 질문

| 질문 | 답 |
|---|---|
| AI 가격이 틀리면? | 범위를 0.4~2.5배로 자르고, 앱 안 같은 종류 시세 중앙값을 최대 30% 섞습니다. 신뢰도를 보여 주고, 등록 전에 사용자가 확인합니다. |
| AI 서버가 안 되면? | 카테고리 기준가 × 상태 감가율로 추정하고 "기준가 추정(AI 미연결)"으로 표시합니다. 등록은 멈추지 않습니다. |
| 왜 WebSocket? | 교재 1장 비교표대로, 채팅은 양쪽이 아무 때나 보내므로 WebSocket이 맞고, 앱이 꺼져 있을 때는 OS 푸시(FCM)에 맡깁니다. 폴링은 배터리를 낭비합니다. |
| 두 사람이 동시에 수락하면? | 물건 테이블의 `@Version` 낙관적 잠금으로 한쪽만 성공하고 나머지는 409입니다. |
| 가중치 근거? | "교환은 가격이 맞아야 시작된다"를 가장 크게 두고 양쪽 선호를 그다음에 뒀습니다. 상수로 분리해 데이터가 쌓이면 성사율로 조정할 수 있습니다. |
| API 키는? | `application-local.properties`(Git 제외)나 환경변수에만 둡니다. 레포에는 예시 파일만 있습니다. |

## 4. 시연 중 문제가 생기면 (12장 2.3)

| 현상 | 먼저 할 것 | 말할 것 |
|---|---|---|
| 로딩이 안 끝남 | 같은 버튼을 다시 누르지 않는다. 서버 cmd 창 로그 확인 | "요청 결과를 아직 확인하지 못했습니다" |
| 연결 오류 | 서버 창이 켜져 있는지, 주소가 10.0.2.2:8097 인지 | "지금은 연결에 실패했고, 수업 전 실행 기록은 smoke-result.txt 입니다" |
| AI가 느림(90초 제한) | 기다리거나 fallback 결과로 진행 | "AI 응답이 늦어 기준가 추정으로 진행합니다" |
| 데이터를 처음 상태로 | 서버 끄고 `sbada-server\data` 폴더를 지우고 다시 켜기 → 시드 데이터 재생성 | |
